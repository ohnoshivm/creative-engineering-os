# Installed ecosystem inventory

The public bundle ships the original Creative Engineering OS core. The wider installed ecosystem is represented by sanitized metadata in [ecosystem-skills.json](../manifests/ecosystem-skills.json) and [ecosystem-plugins.json](../manifests/ecosystem-plugins.json), generated by [catalog-skills.py](../scripts/catalog-skills.py). Third-party skill bodies, plugin code, provider settings, credentials and private configuration are not included by this catalog.

This is an inventory of one installation on **2026-10-20**, not a claim that every listed tool is active, tested, licensed for redistribution, mutually compatible or automatically restorable. Cache presence does not prove installation or activation. A public repository responding successfully does not prove authorship, safety or permission to copy its contents.

## Status and evidence semantics

- **`bundled_core`**: at least one canonical source resolves inside this repository's original `skills/` directory. These 13 skills are the supplied core, subject to the repository license.
- **`upstream_install`**: the scanner found a publicly accessible GitHub origin through a local Git checkout, a plugin's declared repository or a marketplace registry. This is evidence of upstream/distribution origin, **not** a guarantee of exact skill restoration, compatible versions, trustworthy code, authorship or redistribution permission. Check `source_scope`: a marketplace distribution source is not necessarily the skill author's repository. Follow the publisher's install instructions and confirm the skill path, package version and license.
- **`provenance_unknown`**: no independently verified public origin was established from the allowed metadata. Do not guess a repository, fetch similarly named code, or redistribute this installation's files. An unavailable/private URL, failed network check, unsupported host or absent metadata can all produce this status.

A skill has a content-derived ID, declared names/folders, SHA-256 file hash, home-relative discovery paths, canonical sources, source evidence, plugin package links and license evidence. Identical skill-file bytes do not imply identical support files. Git commits describe checkout HEAD, not a clean-tree attestation or proof that the installed skill bytes exactly match that commit. Plugin versions/cache revisions and registry commits are distinct fields; no source ref or commit is invented from a version string.

Plugin entries distinguish `registered_installed`, `registered_cache_not_in_scanned_roots` and `cache_present_activation_unverified`. Codex cache records are not an activation registry. The Claude registry had duplicate records for some plugins; `registered_records` preserves that count without publishing account, scope or install timestamps.

License labels come from skill frontmatter, a nearby license notice or plugin manifest. Nearby notices may have a different scope; metadata may be incomplete or conflicting. Proprietary and unknown entries are retained as inventory records, never treated as an open-source grant. Before vendoring or installing upstream code, inspect its exact release, applicable license and dependencies. Even a recognized permissive label here is not an automated redistribution approval.

## Restore upstream capabilities deliberately

Install the original core using this repository's installer. Treat the remaining ecosystem as optional and project-specific. The catalog does not contain an “install all 907” command.

For a publisher-managed Claude plugin already identified by marketplace and name, use Claude's plugin interface. For example, the inventory records `frontend-design@claude-plugins-official` and a public official marketplace origin:

```text
/plugin marketplace add anthropics/claude-plugins-official
/plugin install frontend-design@claude-plugins-official
```

These commands request the publisher's currently offered plugin, not a guarantee of restoring this snapshot's cache revision. Review that publisher's available versions, license and installation instructions. Do not copy a local cache folder or assume another provider accepts the same plugin package. Connector plugins can require separate account setup, which this repository does not export.

For a directly evidenced Git skill repository, an isolated upstream checkout lets you inspect it before choosing its publisher-supported installation method. For example:

```sh
git clone https://github.com/Leonxlnx/taste-skill.git /path/to/taste-skill
```

Then inspect that repository's README/license, compare the manifest's `sources[].commit` with the desired release and check out a reviewed commit if reproducibility is required. Do not run downloaded setup scripts before inspection. A clone alone does not register skills with an agent. The recorded discovery path and content hash help compare installations; they do not grant reuse permission. Unverified origins and refs are withheld from the public catalog.

## Regenerate and review

The scanner uses the Python standard library and reads only the requested skill/cache roots, `SKILL.md`, nearby license notices, Git metadata, allowlisted plugin-manifest fields and the two named Claude registry files. It does not execute installed skills or fetch their support assets.

```sh
python3 scripts/catalog-skills.py --verify-public-repos
```

Without `--verify-public-repos`, public origin candidates are withheld and more records will be marked unknown. Verification uses unauthenticated HTTPS requests, no API token or browser profile. Transient failures receive one bounded retry; failures remain unknown. No account or provider configuration is needed. `--home`, `--bundle-root` and `--output-dir` support fixture testing or a different inventory location.

Review the generated diff before publishing. The scanner emits home-relative paths, replaces opaque application identifiers with `app-<plugin-id>`, removes URL credentials/queries and withholds private/unverified origins and branch names. Plugin fields are allowlisted: names, versions, declared public repository candidates and license labels; the public display name may replace an opaque internal name. Authors, account IDs, install timestamps, provider/auth/MCP configuration and environment values are excluded. A path/hash inventory still reveals which capabilities are installed; publishing it is intentional here.

Validation performed: alias and exact-content deduplication, root counts, backup exclusion, core detection, plugin-version/registration distinction, URL credential stripping and fixture secrets excluded from output. The catalog is not a security scan of upstream code. Keep the unknown counts visible, and never replace them with assumed provenance.
