# Optional tooling decisions

Reviewed **2026-10-20** against first-party documentation/repositories. These are adoption recommendations, not installed-tool claims. **Nothing was installed by this evaluation.** No global packages, browser extensions, editor accounts or default-stack changes were made. Recheck the exact release, license, peer dependencies and project lockfile before adoption. Runtime compatibility and performance remain untested here.

## Adoption experiments and exit criteria

These experiments have not run. They are small ways to prove a tool's value before committing the application to it.

- **Theatre:** author a five-second original camera/property sequence, export state, reload a clean build and verify the production bundle excludes Studio. Keep a reduced-motion pose and ordinary content navigation. Confirm release/package licenses rather than relying only on the repository badge.
- **Rive:** integrate one owned .riv asset behind a semantic HTML control; test loading failure, resizing, high DPR, focus/keyboard input and reduced motion. Measure JS/WASM/asset bytes and cleanup after unmount. Confirm export conditions with the current plan before publishing.
- **Motion/Lenis/Tempus:** first map frame and scroll ownership. Compare a representative input trace before/after; verify anchors, history navigation, nested overflow, touch and reduced motion. A scheduler does not inherently make GPU work cheaper. If GSAP drives Lenis, disable independent auto-rAF and remove ticker callbacks on teardown; follow docs for the pinned version and time units.
- **OGL/R3F:** implement the same small original scene with the selected stack and assess code/lifecycle complexity, transferred bytes and runtime cost. Match R3F's React major and Three peer requirements. Do not update React solely to add a decorative scene.
- **WebGPU/TSL:** pin Three.js, use docs for that revision, check required features and compile representative materials/postprocessing. Test GPU availability, device loss, WebGL2 backend and unsupported-device fallback. WebGPU is not automatically faster for a given scene; keep before/after traces and visual comparisons.
- **canvas-sketch:** create one seeded export, rerun from a clean checkout, and retain seed, dimensions, dependency lock and source. Exported assets can be delivered without embedding its authoring environment.
- **OGPU:** first confirm the intended repository. For oframe/ogpu, review current README/license and package structure; build one isolated sample in a secure context with capability detection. Do not copy a repository's entire workflow into an existing app or assume feature parity with Three.js.
- **KTX:** retain original textures; encode one colour map and one normal/data map using correct colour semantics and mipmaps. Compare ETC1S/UASTC quality, transfer size, GPU memory and transcoding startup on target devices. Configure KTX2Loader's transcoder files and renderer support detection for the exact Three.js release; account for CSP, worker and asset-host paths. Smaller disk size alone is insufficient.
- **Spector.js:** use a development page with representative data, capture a single WebGL frame, inspect commands/textures/shaders/framebuffers, and export a capture as evidence. Fix one demonstrated issue, then compare captures plus a browser trace. Capture may perturb execution, so do not report its overhead as ordinary runtime. Keep captures free of private assets; remove injected scripts from production. Use dedicated WebGPU tooling for WebGPU analysis.

## Sources and limits

All links above were checked live on 2026-10-20. The Spector project site initially returned content but a later fetch timed out; its official repository remained retrievable. OGL's standalone LICENSE URL did not retrieve successfully; the official package metadata states Unlicense. These checks do not certify a dependency tree, software supply chain, binaries, browser extension or legal suitability. Recheck artifacts actually selected by the project.

The decisions favor reversible, project-scoped trials. They authorize no installation and claim no benchmark result. The baseline remains the existing project conventions, native platform features, and the smallest toolset supported by measured needs.
